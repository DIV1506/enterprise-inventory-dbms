##### Demo 1: LOST UPDATE prevented by row locking (SELECT ... FOR UPDATE) #####
start qty = 100.  Session A issues 30 (holds the lock 3s); Session B issues 20 one second later.
Session B waited ~2s for Session A's lock.
final qty = 50   (expected 50 -> no lost update)

##### Demo 2: ISOLATION LEVELS - non-repeatable read #####
  READ COMMITTED  first read : 100
  READ COMMITTED  second read: 40
  REPEATABLE READ  first read : 100
  REPEATABLE READ  second read: 100
(READ COMMITTED sees the other session's committed change; REPEATABLE READ keeps its snapshot.)

##### Demo 3: DEADLOCK - two sessions lock the same two rows in OPPOSITE order #####
  [session 1] ERROR:  deadlock detected
